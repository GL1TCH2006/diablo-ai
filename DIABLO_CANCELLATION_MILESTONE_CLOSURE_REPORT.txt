CANCELLATION LIMITATIONS (Documented)
================================================================================

1. BLENDER execute_script - NO COOPERATIVE MID-SCRIPT CANCELLATION
---------------------------------------------------------------------
The execute_script operation runs arbitrary Python code via exec() inside
Blender's main thread. This call blocks Blender's main thread completely.

LIMITATION: Once a script starts executing via exec(), it cannot be
cooperatively interrupted. The script runs to completion or until the
Blender process is externally terminated (via taskkill / process kill).

EVIDENCE:
- blender/scripts/diablo_blender_ops.py:387-396 shows op_execute_script
  uses exec(compile(script, ...), namespace) which blocks Blender's main thread
- Blender's main thread is blocked during exec(); no bpy.app.timers,
  bpy.app.handlers, or modal operators can run
- BlenderRunner polls cancellation at 50ms intervals OUTSIDE the Blender process
- Once Blender starts executing the script, it runs to completion unless
  the entire Blender process is externally killed

DOCUMENTED IN: DIABLO_P1_BLENDER_COOPERATIVE_CANCELLATION_REPORT.txt

IMPACT:
- Long-running scripts cannot be cooperatively interrupted
- Cancellation during execute_script results in full Blender process kill
- User must be aware that execute_script cancellation discards Blender state

MITIGATION:
- Users should structure long scripts with manual checkpoint/yield points
- External process termination (taskkill) remains the fallback
- This limitation is documented and communicated to users

2. UNIX PROCESS-TREE TERMINATION
----------------------------------
The Blender runner's _stop() method uses taskkill /T on Windows for process-tree
termination. On Unix, only the immediate child process is terminated (SIGTERM/SIGKILL).
Child processes spawned by Blender on Unix may survive cancellation.

This is a known limitation documented in DIABLO_EXECUTION_SECURITY_AUDIT.txt.

Agent.respond() 
  -> RequestContext.cancellation_token (CancellationToken)
  -> ToolExecutionContext.cancellation_token 
  -> Tool._tool_context.cancellation_token
  -> Tool.run_script() / run_command() / BlenderCapabilityLayer._run()

TERMINATION HIERARCHY:
1. Pre-flight: cancellation_requested() check before spawn
2. Mid-execution: 50ms polling loop in runner
3. On cancel: 
   - Python/Terminal: terminate() -> wait 5s -> kill() -> wait 5s -> reap
   - Blender: taskkill /T /F /PID (Windows) or terminate/kill (fallback)
4. Cleanup: reader threads joined, pipes closed, process reaped

OUTCOME CLASSIFICATION:
- cancelled=True: User requested cancellation, process terminated
- timed_out=True: Process exceeded timeout, terminated
- success=False, cancelled=False, timed_out=False: Process failed on its own
