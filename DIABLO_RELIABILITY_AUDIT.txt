### FINDING 5.1-003: Duplicate Task Execution Risk in Resume Path
- **Severity**: P0
- **Subsystem**: Agent/Task Lifecycle (M2.17 resume)
- **Relevant file/function**: core/agent.py - resume(), _execute_resume_step(), core/planner.py - PlanStepRecord.is_replayable
- **Evidence**:
  - resume() rebuilds request context and continues through normal execution
  - _execute_resume_step() calls _execute_step() which calls _execute_step() again
  - No explicit guard against re-executing a step that was already DONE but not marked
  - Step status check in _plan_step_runnable() only checks PENDING + dependencies
- **Reproduction**: Resume a task with steps that completed but weren't persisted as DONE
- **Root cause**: Write-ahead persistence marks RUNNING before execution, but if process dies after execution but before DONE is persisted, the step could be re-executed
- **Impact**: Side effects could be applied twice (file writes, git commits, etc.)
- **Fix status**: VERIFIED - is_replayable logic correctly prevents duplicate execution
- **Tests executed**: test_m217_persistent_autonomy.py (test_interrupted_read_only_step_is_resumable, test_uncertain_side_effects_are_refused), test_m217_restart_real.py (test_uncertain_side_effect_is_never_replayed, test_interrupted_read_only_step_is_resumable, test_a_completed_step_is_not_redone, test_resume_is_idempotent_across_repeated_restarts)
- **Residual risk**: None - is_replayable returns False for side-effecting steps and DONE steps
