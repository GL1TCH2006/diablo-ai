# M2.14 Phase 10R — Architecture / Security / Boundary Audit

**This is a new milestone.** Neither 10R nor 10Q existed before this one; see
`docs/M2.14_PHASE10Q_VALIDATION.md` for why. This is an audit of the system as
it stands. It does not redesign anything, and no finding below changed frozen
architecture except where explicitly marked as a defect with a minimal fix.

## Method

Every claim in this document was checked against the repository, by reading the
authoritative layer or by running the named test. Findings are classified:

* **PASS** - the property holds, and something would notice if it stopped.
* **DEFECT** - the property does not hold, or an assertion does not test what it
  claims to. Fixed here, or recorded as unfixed with the reason.
* **LIMITATION** - works, but with a narrower envelope than a reader might
  assume. Not a bug.
* **DEFERRED** - out of scope for Phase 10; belongs to a later milestone.

A missing feature is a LIMITATION or DEFERRED, never a DEFECT.

## Findings summary

| ID | Class | Summary | Resolution |
|---|---|---|---|
| G6-a | DEFECT | A real-model test asserted tool *selection* rather than persistence; its guard made the tested branch unreachable for one model class | Fixed in 10Q: reported, not asserted; the underlying persistence property is asserted structurally in `tests/test_phase10q_validation.py` |
| G6-b | DEFECT | A "read-only session changed the data" assertion was false by design — every request projects its own task node | Fixed in 10Q: replaced with the stronger claim — no node lost, count grew by exactly the second session's own task, file knowledge intact |
| A6/C7/C8/D8 | PASS (Phase 10A) | The terminal verdict had no single written authority; two tests contradicted each other | Fixed in Phase 10A: one invariant, enforced at the state machine, documented in the contract doc |

Both 10Q defects share one root cause: a test asserting a fact about a **model**
where it claimed to assert a fact about a **store**. Neither is an architecture
fault, and neither indicated a defect in the system under audit. They are
recorded because they were real and are now fixed, and because an audit that
found nothing would be indistinguishable from an audit that did not look.

Unchanged limitations carried forward, restated so 10R does not appear to have
fixed them: F3 (Blender running-child cancellation), B5 (step-level correlation),
G7 (`DebugLoop` narrower tool set), G8 (single-model observations), plus the
pre-existing list at `cross_layer_execution_contracts.md:663` and the "Do not fix
merely because it is listed" list in the Phase 10 handover §8.
