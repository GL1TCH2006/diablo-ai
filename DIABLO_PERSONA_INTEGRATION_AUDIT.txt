SECTION B: PRODUCTION REPLY FLOW — EXACT CALL GRAPH
================================================================================

1. APPLICATION ENTRY POINTS
----------------------------
Terminal UI: ui/terminal.py → TerminalUI._answer() → Agent.respond()
Edge Companion: ui/edge_companion.py → EdgeCompanionApp._on_submit() → CompanionController.submit_task() → bridge.submit_message() → Agent.respond()

2. USER MESSAGE → AGENT EXECUTION PATH
---------------------------------------
Agent.respond(user_input)
  └─ _respond(user_input)
      ├─ _begin_request_context()          # Fresh RequestContext per turn
      ├─ _tasks.begin_task(user_input)     # Creates TaskRecord
      ├─ _capture_plan_goal(user_input)    # Stores pending goal
      ├─ _create_run_record()              # Persists TaskRecord
      ├─ _planner.matches_greeting()       # Fast path
      │   └─ greet_response() → GREETING   # "Hello. Diablo is online."
      ├─ _planner.fast_intent()            # Desktop intent (open_app, etc.)
      │   └─ _run_intent() → intent-specific reply
      └─ _llm_loop()                       # Full LLM planning + execution
          ├─ build_system_prompt()         # Core system prompt
          ├─ _reference_sections()         # Memory, rules, project context
          ├─ _messages (conversation)      # Prior turns
          ├─ _select_model()               # Model router
          ├─ _chat_with_fallback()         # Provider call with fallback
          ├─ ExecutionPlan.from_tool_calls()  # Plan from tool calls
          ├─ _desktop_mismatch_correction()   # Wrong-tool recovery
          ├─ _begin_plan()                 # Persist plan
          ├─ _execute_step() → _executor.execute() → ToolRegistry → ToolSpec.fn()
          ├─ _record_verification()        # VerificationLedger
          └─ Returns reply text (str)

3. SYSTEM PROMPT ASSEMBLY
--------------------------
build_system_prompt(model_label, project, workspace_root) → str
  Returns: system prompt text (core/constants.py, core/context.py)
  Includes: model identity, project context, workspace root, tool descriptions
  Persona influence: NONE (personas not wired into agent)

4. MODEL SELECTION
-------------------
_select_model(user_input) → core/agent.py
  Uses ModelRouter (ai/model_router.py) with catalog, mode (fast/strong), fallbacks
  Persona influence: NONE

5. FINAL ASSISTANT RESPONSE PRODUCTION
----------------------------------------
Returns from _llm_loop(), _run_intent(), greet_response(), or intent handlers
All return plain str → TerminalUI._answer() prints: "DIABLO: {reply}"
Edge Companion: reply goes through bridge → CompanionController → UI snapshot

6. INTERACTION WITH SAFETY SYSTEMS
-----------------------------------
- Permissions: PermissionManager.evaluate() before tool dispatch (config/permissions.py)
- Verification: _record_verification() → VerificationLedger.adjudicate() (core/verification_ledger.py)
- Cancellation: CancellationToken checked in _llm_loop(), _execute_step()
- Memory: _reference_sections() includes conversation, rules, project memory
- Tool permissions: ToolSpec.level, ToolSpec.level_for() evaluated per call
- None of these import or reference personas

7. PERSONA CANNOT OVERRIDE SAFETY
---------------------------------
- No import of personas in config/permissions.py (proven by test_personas.py:332-341)
- No import of personas in core/executor.py or core/verification_ledger.py
- Persona module is strictly presentation data with fail-closed loader

--------------------------
Canonical name: "raphael"
Description: "Formal and precise. States the verification status of a result before its substance, names confidence and residual risk explicitly, and never implies certainty it does not have."
Aliases: ["raphael", "rafi", "raf", "the formal one", "precise"]
Replies: Mapping for all 5 OUTCOMES (completed, failed, unverified, approval_required, cancelled)
  Templates include: {details}, {detail}, {risk}, {confidence}, {outcome_label}
  Completed: "Completed and independently verified. {details} Confidence: {confidence}. Residual risk: {risk}."
  Failed: "This did not complete. {details} I am reporting the failure rather than a partial result. Residual risk: {risk}."
  Unverified: "This finished, but it was not independently verified, so I am not calling it a success. {details} Confidence: {confidence}. Residual risk: {risk}."
  Approval_required: "I am holding. {details} Your decision is required before I proceed; nothing has been changed yet. Residual risk: {risk}."

Orb palette: "gold"
Voice: enabled_by_default=False, rate=-1, pitch=0, voice_hint="Prefer a measured delivery..."
Risk policy: always_state_risk=True, confidence_wording="explicit"

Validation rules (fail closed):

- description: required non-empty string

- voice/risk_policy: optional mappings, unknown keys tolerated
- Unknown outcome in format_status() → falls back to "unverified" (never success)

Caching: _cache dict, failures stay failed (no retry-by-accident)
Alias index: deterministic (sorted by name, longest alias first)
Select_persona(): Matches aliases on word boundaries, leading wake words stripped

SELECTOR: Not a separate file; select_persona() in loader.py
  Resolution order:
  1. Alias as whole word sequence in text (longest first)
  2. Alias equals normalized text
  3. DEFAULT_PERSONA ("sage")

  - Substitutes {details}, {detail}, {risk}, {confidence}, {outcome_label}

  - risk="none observed" for completed, else "as described above"

SECTION E: RECOMMENDED DESIGN — OPT-IN PRESENTATION STYLES (B)
================================================================================

RATIONALE
----------
1. Personas are explicitly documented as "presentation only" and "not wired into the agent"
2. The loader/selector already exists with fail-closed validation
3. Design B respects the documented architecture: personas are opt-in styling, not authority
4. DEFAULT_PERSONA = "sage" is already the documented default (loader.py:69)
5. Design B keeps the safety invariant: core policy, task instructions, and presentation remain separate
6. Design A wastes working code; Design C forces a choice the docs say is undecided
7. Test_personas.py already proves isolation; Design B extends that to runtime without crossing boundaries

IMPLEMENTATION SCOPE (SMALLEST EFFECTIVE CHANGE)
-------------------------------------------------

Files to change (minimal set):
1. core/agent.py: Add optional persona parameter to _respond() and _llm_loop() — OR wrap reply at the end of _respond()
   Recommendation: Wrap at end of _respond() — keeps Agent unaware of personas, only TerminalUI/Companion know

2. ui/terminal.py: TerminalUI._answer()
   - Resolve persona: persona = select_persona(text)  # from user input aliases
   - After Agent.respond(): reply = format_status(persona, outcome, details)
   - Need to determine "outcome" from task state (verification, task status)

3. ui/edge_companion.py: EdgeCompanionApp._on_submit() or bridge
   - Resolve persona from user input
   - Pass persona to bridge → format_status on reply

4. config/default_config.toml: Add optional [persona] section
   default = "sage"  # or "auto" for alias-matching from request

5. ui/orb/state_map.py: Map persona.orb_palette_key → PALETTES for visual state

SAFETY BOUNDARIES (MUST PRESERVE)
---------------------------------
✓ Persona never imported in config/permissions.py, core/executor.py, core/verification_ledger.py
✓ Persona only wraps final reply text via format_status()
✓ format_status() outcome must come from TaskState/VerificationState, never from persona
✓ format_status() falls back to "unverified" for unknown outcomes
✓ select_persona() falls back to DEFAULT_PERSONA ("sage") on no match
✓ Persona never grants tool access, bypasses approval, suppresses failures
✓ Persona templates never say "completed" for unverified outcomes (loader enforces this)
✓ Persona cannot inject unbounded content (details truncated to 400 chars)
✓ User explicit instructions always take precedence (persona is presentation only)

PROPOSED CONFIGURATION / API
-----------------------------
config/default_config.toml:
  [persona]
  # "auto" = match aliases from user input; "sage" | "raphael" = force; "none" = disable
  default = "auto"

Terminal command:
  :persona sage        # set session persona
  :persona raphael
  :persona auto        # resume alias matching
  :persona off         # disable, use raw agent reply

API for caller:
  from personas import select_persona, format_status
  persona = select_persona(user_text)  # or explicit name
  outcome = task.verification.value  # "completed", "failed", "unverified", etc.
  details = task.progress_summary
  reply = format_status(persona, outcome, details)
