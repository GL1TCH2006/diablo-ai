FINDING 1: Inconsistent Pre-Flight Cancellation Check
------------------------------------------------------
Severity: MEDIUM
Files: tools/python.py (line 134), tools/terminal.py (line 166), blender/capabilities.py (line 275)
Evidence: 
- python.py line 134: if cancellation_requested(cancel_token): return ToolResult(...)
- terminal.py line 166: if cancellation_requested(cancel_token): return ToolResult(...)
- blender/capabilities.py line 275-279: token = self._cancel_token(); if token is not None and cancellation_requested(token): raise BlenderCancelledError
Finding: Python and Terminal check pre-flight and return ToolResult; Blender raises exception. Inconsistent but functionally equivalent.

FINDING 2: Blender _run() Pre-Flight vs Runner Pre-Flight Race
----------------------------------------------------------------
Severity: LOW
Files: blender/capabilities.py (line 275), blender/runner.py (line 310)
Evidence:
- capabilities.py line 275-279: pre-flight check before runner.run()
- runner.py line 310-315: _spawn_and_collect() also checks _cancelled(cancel_token) before spawn
Finding: Duplicate check. Layer pre-flight raises BlenderCancelledError; runner pre-flight also raises. Redundant but not harmful.

FINDING 3: BlenderRunner._stop() Does Not Kill Process Tree on Windows
-------------------------------------------------------------------------
Severity: HIGH
File: blender/runner.py lines 409-441
Evidence:
- _stop() uses proc.terminate() → proc.kill() only
- No taskkill /T /PID on Windows (unlike terminal.py line 105-107)
- If Blender spawns child processes (e.g., via execute_script with subprocess.Popen), they survive cancellation
Evidence from blender/scripts/diablo_blender_ops.py line 387-393: execute_script allows arbitrary subprocess.Popen
Impact: Blender child processes can survive cancellation, leaving orphan processes.

FINDING 4: Terminal Uses CREATE_NEW_PROCESS_GROUP But Not CTRL_BREAK_EVENT

Severity: MEDIUM
File: tools/terminal.py lines 172-176, 102-107
Evidence:
- Line 176: creationflags = subprocess.CREATE_NEW_PROCESS_GROUP

SECTION 6: REMAINING LIMITATIONS
================================================================================

1. Blender execute_script - No mid-script cooperative cancellation
   - Blender Python script runs to completion once started
   - External kill only; no cooperative cancellation inside Blender Python
   - Arbitrary Blender Python can spawn child processes that survive

2. Blender process-tree termination (Windows)
   - No taskkill /T in BlenderRunner._stop()
   - Child processes spawned by execute_script survive cancellation
   - Terminal tool correctly uses taskkill /T

2. Output buffering - full capture in memory
   - All three runners buffer full output in memory (bounded to 64KB)
   - Long-running high-output commands could exceed memory before truncation applies
   - Mitigation: 64KB limit but still buffered fully first

3. Voice TTS - no cancellation support
   - Fire-and-forget, cannot interrupt speech

4. Voice STT/Wake-word - not implemented
   - Mock only; no real audio processing

4. Blender execute_script - no independent verification
   - Relies on Blender return code only
   - No independent verification of script effects
