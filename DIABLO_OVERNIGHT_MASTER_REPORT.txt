CHANGES MADE
================================================================================

### Fix 1: Task State Transition Validation (P1) - core/agent.py
**Problem**: Agent._transition() silently ignored invalid state transitions by catching
ValueError and only logging a warning.

**Fix**: Removed the try/except block, allowing invalid transitions to fail fast.

**Location**: core/agent.py lines 410-412

**Verification**: 
- test_terminal_state_invariant.py: 32/32 passed
- test_m217_persistent_autonomy.py: 63/63 passed
- test_m217_restart_real.py: 6/6 passed
- All other test suites passing

### Fix 2: Recovery State Registry Unbounded Growth (P1) - core/agent.py
**Problem**: The `_exhausted_task_ids` registry was populated for ALL records during
reconciliation, but only the current task's entry was ever consumed. Other entries
accumulated indefinitely.

**Fix**: 
1. Clear `_exhausted_task_ids` registry after reconciliation completes in `__init__`
2. `resume()` calls `_restore_recovery_state()` for the specific task, repopulating
   only that task's entry

**Location**: core/agent.py lines 137-143 (clear after reconciliation), resume() method

**Verification**: 
- test_m217_persistent_autonomy.py: 63/63 passed
- test_m217_restart_real.py: 6/6 passed
- Custom test verified registry cleared after init (0 entries vs 5 before fix)

### Fix 3: Task Finalization Race (P1) - core/agent.py
**Problem**: _llm_loop() only went through verification phase when task state was
EXECUTING, causing invalid PLANNING -> COMPLETED transition for tasks with no tool calls.

**Fix**: Modified to always call _begin_verification() when verification is NOT_RUN,
regardless of current task state (PLANNING -> VERIFYING is allowed).

**Location**: core/agent.py lines 2922-2929

**Verification**:
- test_terminal_state_invariant.py::test_execution_success_with_nothing_executed: NOW PASSES
- All 32 tests in test_terminal_state_invariant.py pass

### Additional Fix: Recovery State Application for NOOP Resumptions
**Problem**: `_apply_restored_recovery_state()` was only called for actually RESUMED
tasks, not for NOOP (no resumable steps) or REFUSED cases.

**Fix**: Call `_apply_restored_recovery_state()` before early returns in `resume()`.

### Fix: Task ID Timing for Recovery State Application
**Problem**: `_apply_restored_recovery_state()` was called before `begin_task()` set
the task_id, causing registry lookup to fail.

**Fix**: Call `begin_task()` first, then `_apply_restored_recovery_state()`.
